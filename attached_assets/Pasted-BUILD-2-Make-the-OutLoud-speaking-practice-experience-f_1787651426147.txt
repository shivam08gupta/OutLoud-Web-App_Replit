TECHNICAL APPROACH

Use browser-native Web APIs wherever possible.

Camera + microphone:
- Use navigator.mediaDevices.getUserMedia()
- Request camera and microphone only after the user explicitly clicks the permission CTA.
- Display the user's live local camera stream in the existing "You" / "Camera Preview" area.
- Do not upload the video anywhere.
- Do not analyse appearance, eye contact, body language, facial expression, or emotions.
- Stop all media tracks when leaving the practice screen/session.

Audio recording:
- Use the browser MediaRecorder API.
- Record the user's microphone audio while the practice response is active.
- The recording does not need to be uploaded or stored remotely in Build 2.
- Keep the implementation local to the browser.
- Show clear recording state:
  Idle → Recording → Processing → Ready

Speech-to-text:
- Use the browser's Web Speech API / SpeechRecognition where supported.
- Do NOT use OpenAI Whisper, Google Cloud Speech-to-Text, Deepgram, AssemblyAI, or any paid external STT service.
- Do NOT add an API key.
- Do NOT ask me for a credit card.
- The transcript should appear after/during the user's response.
- Preserve the transcript in React state for the current question.

BROWSER COMPATIBILITY:
The MVP will primarily be demonstrated in a modern Chromium browser such as Google Chrome.

If SpeechRecognition is not available:
- Do not fake a transcript.
- Show a clear, friendly message explaining that speech-to-text is unavailable in the current browser.
- Provide an option to retry or use a supported browser.
- Do not crash the application.

→ User sees question
→ User clicks Start Recording
→ Camera + microphone are active
→ Recording begins
→ Speech-to-text captures the response
→ User clicks Stop Recording
→ Recording stops
→ Transcript is available
→ Show a processing state briefly
→ Navigate to the existing AI Feedback screen

For Build 2, the AI Feedback screen must continue using STATIC placeholder feedback.

Feedback screen:
- Show the transcript from the user's actual response.
- Keep the existing feedback UI.
- Clearly label the response as the user's transcript.
- Keep the existing "Try Again" and "Next Question" actions.

Try Again:
→ Return to the SAME question
→ Allow the user to record another response
→ Replace the previous response for that attempt

Next Question:
→ Advance to Question 2
→ Update the indicator to "Question 2 of 3"

Then repeat the same flow for Question 2.

Question 3:
→ Record
→ Stop
→ Transcript
→ Static feedback
→ After feedback, "Next Question" should become "Complete Session" or equivalent.
→ Navigate to Session Complete.
